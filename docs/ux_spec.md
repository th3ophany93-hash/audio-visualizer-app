# Аудио-визуализатор — эталонная UX/функциональная спецификация

Собрано на основе анализа Vibely, Avee Player, Alight Motion, CapCut и общих
конвенций мобильных редакторов. Цель документа — единая точка отсчёта, чтобы
не описывать заново каждый элемент интерфейса в каждой задаче.

Наше отличие от аналогов (сохранить всегда): эффекты и трансформации
применяются к каждому слою независимо, а не глобально ко всей сцене —
именно этого нет в Vibely/Avee.

## 1. Импорт медиа

Аудио:
- Импорт из файловой системы (SAF picker) — уже есть
- Извлечение аудиодорожки из видеофайла
- Показ прогресса декодирования/анализа явно: диалог/оверлей с текстом стадии
  ("Декодирование...", "Анализ частот...", "Готово") + прогресс-бар, не просто
  спиннер без подписи

Картинка/видео-фон:
- Импорт из галереи
- Учёт EXIF-ориентации при загрузке (частая причина "перевёрнутой" картинки)
- Fit-режимы (как в любом видеоредакторе): Fill (заполнить кадр, обрезав
  лишнее), Fit (вписать целиком, с полями), Stretch (растянуть без
  сохранения пропорций) — переключатель из трёх опций
- Ручные трансформации в реальном времени: drag для сдвига X/Y, pinch для
  масштаба, поворот (жест двумя пальцами или слайдер в градусах/радианах)

## 2. Аудио-триммер (отдельный экран/шаг после импорта)

Стандартный паттерн (как в CapCut/InShot):
- Waveform-визуализация всей дорожки на всю ширину экрана
- Два ползунка поверх waveform — левый (начало), правый (конец)
- Play/Pause в центре под waveform
- Перетаскивание левого ползунка — перемотка и проигрывание с этой точки;
  то же для правого (стандартное поведение всех триммеров)
- Область между ползунками визуально выделена (например, светлее/ярче)
- Кнопка "Обрезать/Применить" — прогресс-бар на время обработки — авто-
  возврат на предыдущий экран по завершении с уже обрезанной дорожкой

## 3. Главный экран редактирования

- Превью (GLSurfaceView) — основная область
- Под превью — компактный неинтрузивный таймлайн аудио: play/stop, ползунок
  скраббинга по позиции. Не попадает в финальный экспорт — чисто
  навигационный элемент для удобства редактирования
- Панель верхнего уровня: Выбрать аудио / Выбрать картинку / Экспорт в MP4 /
  Добавить эффект (уже есть)
- Список слоёв (уже есть, раскрывающиеся панели параметров)
- Live-превью должно быть WYSIWYG — то есть все параметры (включая
  audio-reaction) обязаны отражаться на превью в реальном времени при
  воспроизведении, идентично финальному экспорту. Расхождение превью и
  экспорта — баг первого приоритета всегда.

## 4. Параметры слоя (актуальный канонический список)

Уже реализовано — фиксирую как эталон, чтобы не терять при рефакторинге:

Базовые (общие для всех эффектов):
- enabled, opacity, blendMode, scale (x/y), zone/position, color/gradient, z-order

Трансформация (для картинки/видео-слоя отдельно от эффектов):
- position X/Y (drag), rotation (жест/слайдер), scale (pinch/слайдер), fit-режим (fill/fit/stretch)

Движение:
- movementEnabled, speed, direction

Аудио-реакция:
- reactionMode (NONE / AMBIENT_ONLY / SMOOTH_CLIMAX / BEAT_PULSE), beatFlicker (bool),
  frequencyBand (BASS/MID/TREBLE/FULL), sensitivity, attack/release (smoothing)

Частицы: count, size (+вариативность), spawnRate, lifetime, gravity/direction

Туман: density, noiseScale, driftSpeedX/Y

## 5. Общие паттерны обратной связи (применимо везде)

- Любая операция дольше ~1 сек — прогресс-бар с текстовой стадией, не голый спиннер
- Любая деструктивная операция (обрезка, удаление слоя) — либо undo, либо
  подтверждение
- Успешное завершение долгой операции — явный визуальный сигнал (не просто
  тихо вернуться на предыдущий экран)

## 6. Экспорт

Уже есть базовый MP4-экспорт. Стандартный набор опций у аналогов, которого
пока нет:
- Выбор разрешения (например, 720p/1080p/1440p)
- Выбор соотношения сторон (9:16 для Shorts/TikTok, 1:1, 16:9)
- Индикатор прогресса рендера с оценкой оставшегося времени

## Как использовать этот документ

Ссылаться на конкретный раздел вместо переписывания требований заново,
например: "Реализуй аудио-триммер по разделу 2 спецификации" — и Claude Code
сможет пойти в этот файл (если он лежит в репозитории) или ты просто
скопируешь нужный раздел в задачу.
